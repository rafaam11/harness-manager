# v3.5.0 — 기존 Node 보호와 AI 설치 복구

셋업이 기존 MSI Node를 NVM으로 무인 이관해 실행 경로가 사라질 수 있던 문제를 막았습니다. 설치에 실패하면 위저드에서 이 PC의 Codex 또는 Claude Code에 해결을 요청할 수 있습니다.

## 기존 Node 보호

- 정상 Node 22.12 이상과 npm은 그대로 유지합니다. 기존 Node가 있으면 NVM을 자동 설치하거나 활성 버전을 바꾸지 않습니다.
- MSI/NVM 혼재, 서로 다른 Node 설치본, 실행 실패는 진단 결과에 표시하고 자동 변경을 중단합니다.
- Node가 없는 환경에서는 NVM → `nvm install 22` → 정확한 버전 `nvm use` → 실제 경로·버전·npm 검증을 수행합니다.
- 앱과 bootstrap이 같은 보호 검사를 사용합니다. 앱에도 스크립트를 포함하므로 연결한 레포가 오래되어도 보호 검사가 적용됩니다.
- 설치 후 PATH/NVM 환경을 갱신하고 기존 터미널과 호스트 앱의 재시작을 안내합니다. 설치 로그를 파일로 저장합니다.

## AI에게 해결 요청

- 위저드와 설치 화면에 **Codex에게 해결 요청**, **Claude Code에게 해결 요청** 버튼을 추가했습니다.
- 설치된 CLI와 기존 로그인 계정을 사용하며, 실패한 항목의 계획·오류·최근 로그를 전달합니다. CLI가 실행되지 않으면 다른 AI나 터미널에서 조치하도록 안내합니다.
- 작업 출력과 승인 요청을 앱에서 확인합니다. 명령 실행·파일 수정은 내용을 검토해 이번 요청만 승인하거나 거절할 수 있습니다.
- AI 작업 뒤 실제 설치 상태를 재검사합니다. 필요한 설치 재실행은 별도로 확인받고, 문제가 남으면 새 오류를 전달해 최대 3회 시도합니다.
- 복구 중단, 설치와의 동시 실행 방지, 화면 재진입 시 상태 복원, 비밀값을 가린 복구 로그를 지원합니다.

## 검증

- vitest 52개 파일·296개 테스트, 타입 검사, 프로덕션 빌드를 통과했습니다. Node 보호·정확한 버전 활성화·AI 승인/거절·취소·재시도 상한·IPC 입력·화면 흐름을 검증했습니다.
- 실제 자식 프로세스와 Windows `.cmd` 경로에서 한글·특수문자 전달과 프로세스 종료를 검증했습니다.
- Codex 0.164.0과 Claude Code 2.1.311의 실제 초기 연결을 격리된 임시 설정에서 확인했습니다. 실제 계정으로 유료 AI 작업을 실행하거나 시스템 패키지를 변경하는 시험은 하지 않았습니다.
- 신규 PC의 실제 NVM 설치는 모의 테스트로 검증했습니다.
- 격리된 Electron 화면에서 모의 실패 → 해결 요청 → 승인 → 재검사 완료 흐름과 화면 표시를 확인했습니다.

## 업데이트

- 기존 앱에서 자동 업데이트하거나 이 릴리스의 설치 파일을 실행하세요.
- 기존 Node 중복 설치나 MSI 등록을 자동 제거하지 않습니다. doctor 결과에 따라 사용자가 정리 방식을 결정합니다.
