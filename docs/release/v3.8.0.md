# v3.8.0 — Codex 플러그인 진단과 선택형 mod

Codex에 설치한 플러그인과 새 세션에 노출되는 스킬을 구분해 확인할 수 있습니다. Codex용 상태 조회·외부 CLI 관측·선택형 가드 패키지도 추가했습니다.

## Codex 카탈로그와 스킬 진단

- Codex CLI의 실제 설치 목록과 활성 상태를 Claude 목록과 나란히 표시합니다. 같은 ID도 provider별로 구분하며, 목록 조회 실패는 경고로 알립니다.
- 카탈로그의 **Codex 스킬 인식 진단**은 새 프롬프트 입력 미리보기의 스킬 이름을 조회합니다. 기준 폴더를 표시하며, 다른 프로젝트나 이미 열린 세션의 결과는 다를 수 있습니다.
- 마켓플레이스 원본과 설치 캐시는 다릅니다. Git 소스는 `codex plugin marketplace upgrade <이름>`으로 갱신하고, `codex plugin add <플러그인@마켓플레이스>`로 캐시를 갱신한 뒤 새 세션에서 확인합니다.

## 선택 패키지 jinmin-codex

- `codex plugin add jinmin-codex@jinmin`으로 설치합니다. Git 마켓플레이스는 먼저 최신화해야 새 패키지가 보입니다. 설치 후 새 세션에서 hook을 검토·신뢰해야 합니다. 기본 공통 프로필에는 자동 설치하지 않습니다.
- `codex-status` 스킬로 모델·권한·세션·도구·에이전트의 마지막 관측값과 Git 상태를 확인합니다. 토큰·비용·한도는 추정하지 않습니다. Claude의 입력창 위 HUD와 같은 렌더링은 제공하지 않습니다.
- 셸 도구에서 직접 실행한 별도 Codex·Claude CLI의 시작과 도구 반환을 관측하고, 반환 시 메시지를 표시합니다. 분리 실행한 프로세스의 생존이나 성공은 보증하지 않습니다.
- 가드는 기본 꺼짐입니다. `HM_CODEX_GUARD=block`인 세션에서 기존 Claude guard와 같은 탐지기로 위험 명령을 차단합니다. Codex hook의 승인 질문은 지원되지 않으므로, 차단된 명령은 사용자가 검토 후 직접 실행합니다. 완전한 보안 경계는 아닙니다.
- MCW v1.54.0은 자체 hook으로 모델·권한·도구 칩과 작업 중·입력 대기 상태를 표시합니다.

## cua-driver 설치

레포 manifest의 수동 설치 안내를 공식 `irm https://cua.ai/driver/install.ps1 | iex` 설치 단계로 바꿨습니다. 개인 프로필의 설치 정의를 자동 덮어쓰지는 않습니다. 설치 스크립트에 고정 버전을 전달하지 않으므로 manifest의 버전 표시는 버전 pin을 보증하지 않습니다.

## 검증

- Windows에서 Vitest 62개 파일·325개 테스트, 타입 검사, 프로덕션 빌드를 통과했습니다.
- Codex mod 테스트 3개와 마켓플레이스·플러그인 validate를 통과했습니다. 플러그인 디렉터리 제출용 라이선스·아이콘 검사는 충족하지 않으며, 이번 배포는 개인 마켓플레이스를 사용합니다.
- Codex CLI 0.162.1을 임시 홈과 로컬 고정 응답 모델에 연결해 스킬 노출·실제 hook 실행·위험 명령 차단·세션 종료 상태 저장을 확인했습니다. 사용자 로그인과 유료 API는 사용하지 않았습니다.
- 외부 CLI 종료 메시지는 단위 테스트로 확인했습니다. 실제 중첩 `claude -p` 실행은 자동 실행 검토가 차단해 검증하지 못했습니다. cua-driver 실제 설치도 실행하지 않았습니다.
