# v5.1.0 — 내 설정에 추가한 독립 도구도 진단·설치

프로필의 `manifest/tools.json`에 넣은 도구를 상태판과 설치 화면이 모두 다룹니다. 지금까지 doctor는 Claude Code·Codex·cua-driver만 검사해서, 그 밖의 도구를 정의에 넣어도 "정보"로만 남고 새 PC에 설치되지 않았습니다.

- **툴체인 카드:** 전용 카드가 없는 도구를 툴체인 카드에서 검사합니다. 설치 범위(core/dev/full) 밖의 도구는 건너뜁니다. 빠진 도구는 설치 화면의 할 일이 되며, `powershell-script`·`npm`·`winget` 방식은 자동으로 설치하고 `manual` 방식은 안내 문구를 보여 줍니다.
- **설치 파일 위치로 확인:** 트레이 GUI 앱처럼 PATH에 올라가지 않는 도구는 `verify: { "path": "~/…" }`로 설치 파일이 있는지 확인합니다. 개인 경로가 정의에 남지 않도록 `~/`로 시작하는 경로만 허용하며, 다른 형식은 manifest 검사에서 오류로 막습니다.

## 호환성

`verify.path`를 쓴 정의를 이전 버전 앱이 읽으면, 그 도구는 PATH 명령으로 검사되어 없음으로 보일 수 있습니다. 이 정의를 동기화하는 PC는 v5.1.0 이상으로 업데이트하세요. 기존 `verify.command`·`args` 정의는 그대로 동작합니다.

## 검증

단위·계약 테스트 전체, 타입 검사와 프로덕션 빌드를 확인했습니다. 실제 PC의 개인 프로필에 PATH 방식 도구 하나와 설치 파일 위치 방식 도구 하나를 넣고, 개발 빌드의 `hm manifest validate`·`hm doctor`·`hm install` 미리보기로 정상 판정과 "할 일 없음"을 확인했습니다. 앱 화면은 실측하지 않았습니다.
