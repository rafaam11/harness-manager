# v3.6.0 — 사용자 프로필과 병렬 AI 설치 복구

공개 앱의 기본 설정과 사용자별 설치 정의를 분리했습니다. 실패한 설치 항목은 Codex 또는 Claude Code로 병렬 복구하고, 공통 앱 버그는 검증한 소스 수정으로 이어갈 수 있습니다.

## 사용자 프로필

- 위저드 첫 화면에서 사용자 프로필을 선택·복사하거나 외부 폴더를 연결합니다. 별도로 클론한 비공개 Git 프로필도 연결할 수 있습니다.
- 공통 기본은 Git·Node·Claude Code·Codex만 관리합니다. 개인 모델·권한·플러그인·MCP·dotfiles는 자동 적용하지 않습니다.
- 기존 jinmin 설정은 `legacy` 프로필을 명시적으로 선택할 때만 적용됩니다. **업데이트 뒤 기존 구성을 계속 관리하려면 위저드에서 기존 jinmin을 선택하거나 개인 사본으로 복사하세요.** 선택만으로 현재 PC 설정을 바꾸거나 삭제하지 않습니다.
- `core / dev / full`은 선택한 사용자 프로필 안의 설치 범위입니다.
- doctor·install·capture는 선택한 프로필만 사용합니다. 앱 소스 위치, 프로필 정의, PC 전용 보완 설정을 분리합니다. 프로필이 손상되거나 없어지면 다른 프로필로 대체하지 않습니다.
- CLI에 `hm profiles list/create/connect/use`를 추가했습니다. 비공개 원격 저장소 생성과 동기화는 사용자가 관리합니다.

## 병렬 AI 복구

- 실패 항목별 Codex·Claude Code 버튼과 일괄 요청을 지원합니다. 최대 3개를 병렬 실행하며, 같은 provider 설정·공용 플러그인·MCP·런타임 변경은 실행 순서를 지킵니다.
- 작업별 로그·상태·중단 버튼을 제공합니다. 중복 요청을 막고 대기 중인 작업도 취소할 수 있습니다.
- 요청 시 안내 후 Codex `--dangerously-bypass-approvals-and-sandbox`, Claude Code `--dangerously-skip-permissions`로 실행합니다. 명령·수정마다 확인받지 않습니다. 기존 CLI 로그인 계정을 사용하며, 해당 계정의 사용량이 발생할 수 있습니다.
- 항목별 최대 3회 복구하고 실제 상태를 재검사합니다. 앱 종료 시 실행 중·대기 중 복구를 취소하고 프로세스 트리 종료를 기다립니다.

## 공통 소스 개선

- HM 원격 저장소의 별도 dev 클론에서 공통 버그와 회귀 테스트를 수정합니다. 사용자가 작업 중인 원본 레포는 건드리지 않습니다.
- 호스트가 공개할 파일 범위·홈 경로·비공개 낱말·비밀값을 확인하고 `npm test` → 타입 검사 → 빌드 후 커밋합니다. 개인 프로필은 공개 HM 소스에 반영하지 않습니다.
- 동시 수정의 fetch·merge·재검증·push는 하나씩 진행합니다. 충돌, 테스트 실패, 푸시 권한 부족은 사본과 로그를 남기고 소스 반영 상태로 표시합니다. 자동 태그·앱 릴리스는 만들지 않습니다.
- YOLO CLI는 사용자 계정 권한으로 동작하며 일반 설치 엔진의 파일 allowlist로 격리되지 않습니다. 시스템 패키지 제거·MSI/NVM 이관은 자동 실행하지 않도록 복구 지침에 명시합니다.

## 함께 반영한 수정

- 설치 diff의 방향을 `이 PC → 레포`로 정확히 표시합니다.
- 격리 실행(`HM_HOME`)이 실제 Windows 문서 폴더의 PowerShell 프로필을 참조하지 않도록 했습니다.
- README와 상태판·설치 화면 설명을 현재 기능에 맞게 갱신했습니다.

## 검증

- vitest 55개 파일·303개 테스트, 타입 검사, 프로덕션 빌드.
- 실제 자식 프로세스로 두 CLI의 실행 인자·한글·특수문자 전달·취소 검증. 실제 유료 AI 작업이나 시스템 패키지 설치·제거는 시험하지 않았습니다.
- 임시 Git 원격 저장소로 병렬 수정의 커밋·병합·재검증·푸시와 검증 실패 시 중단을 확인했습니다.
- 임시 홈에서 프로필 생성·선택·설치 계획을 확인했습니다. Electron 화면에서 프로필 표시, 두 작업 동시 진행, 한 작업만 취소하는 흐름을 확인했습니다.
