# v3.0.0 — 새 PC 셋업과 상태판

Harness Manager가 "로컬 환경 뷰어"에서 **개인 CLI 개발환경을 레포 한 곳으로 맞추는 도구**로 바뀌었습니다.
레포를 clone하고 셋업 위저드(또는 `scripts/bootstrap.ps1`)를 실행하면 툴체인, Claude Code·Codex 설정, 플러그인, MCP,
스킬, dotfiles가 manifest와 같아지고, 첫 화면의 상태판이 무엇이 맞고 무엇이 빠졌는지 보여 줍니다.

## 새 기능

- **상태판**(첫 화면): 카드 8개(툴체인, Claude Code, Codex, 플러그인, 스킬, MCP, cua-driver, dotfiles)에 정상·주의·누락을 색과 글자로 보여 줍니다. 섹션 탭에서 항목별 상세를 봅니다.
- **설치**: 정상이 아닌 항목마다 무엇을 실행하고 어떤 파일을 어떻게 고칠지(diff) 먼저 보여 준 뒤, 고른 것만 실행합니다. 로그 창과 작업표시줄 진행 막대가 있고, 두 번째 실행은 이미 맞는 항목을 모두 건너뜁니다.
  - 사용자 설정 파일은 통째로 덮어쓰지 않습니다. `settings.json`은 관리 키만, `config.toml`은 관리 키 줄만(주석 보존), AGENTS.md·PowerShell 프로필은 마커 블록만 바꿉니다. 고치기 전에 원본을 `~/.harness-manager/backups`에 남깁니다.
- **셋업 위저드**(타이틀바 버튼): 진단 → 프로필(core/dev/full) → 항목 → 미리보기(dry-run 가능) → 실행 → 로그인 안내 → 최종 확인.
- **가져오기**: 지금 PC의 설정을 레포 템플릿으로 끌어옵니다. 개인 값(개인 경로, 이메일, 회사 마켓플레이스)은 로컬 프로필로 나누고, 공개 파일에 개인 정보가 남으면 적용을 막습니다.
- **정리 확장**: 깨진 스킬 링크, 플러그인으로 옮긴 스킬의 낡은 사본, claude-hud·v2가 남긴 폴더, 오래된 Codex 로그를 아카이브 후보로 보여 줍니다(삭제하지 않고 이동, 원위치 복구 가능).
- **hm CLI**: 앱이 기동할 때 `~/.harness-manager/bin/hm.cmd`를 둡니다. `hm doctor`, `hm install`, `hm capture`, `hm settings`, `hm repos sync`(업무 프로젝트 레포 일괄 fast-forward, multi-cli-work가 사용)를 앱 없이 쓸 수 있습니다.
- **jinmin 마켓플레이스**: Claude Code mod 5개와 `jinmin-skills` 플러그인을 이 레포가 호스팅합니다(`claude plugin marketplace add rafaam11/harness-manager`). Codex도 같은 마켓플레이스에서 스킬 플러그인을 받습니다.
- 창 프레임·테마·알림을 multi-cli-work와 같은 모양으로 맞췄습니다(Electron 43).

## 없어진 기능

v2의 Timeline, Workspace·git, News, Glossary, GitHub stars, 실행 중 세션, recall, 사용량, 번역 화면을 뺐습니다.
업무 프로젝트와 세션 관리는 multi-cli-work가 맡습니다. 카탈로그, 정리, 설정 편집기는 그대로 있습니다.

## 호환성

- appId가 같아 2.x에서 자동 업데이트로 올라옵니다.
- v2가 남긴 앱 데이터(`~/.harness-manager/board.json`·`projects.json`, `~/.claude/harness-manager`, `~/.claude/backups/harness-manager`)는 읽지 않습니다. 지우지도 않으며, 정리 화면에 아카이브 후보로 보입니다.
- 설정 편집기의 백업 위치가 `~/.harness-manager/backups`로 바뀌었습니다. v2 백업은 새 화면의 백업 목록에 나오지 않습니다.
- 설치·가져오기는 레포 clone 위치가 필요합니다. 처음에는 가져오기 화면이나 위저드에서 레포 폴더를 지정하세요.
- 알려진 한계
  - Windows Terminal 설정은 아직 관리하지 않습니다.
  - cua-driver 설치는 안내만 하고 자동으로 하지 않습니다.
  - Windows 코드서명이 없어 SmartScreen 경고가 뜹니다.

## 릴리스 자산

- Windows: `Harness-Manager-Setup-3.0.0.exe`
- Linux: `Harness-Manager-3.0.0-x86_64.AppImage`, `Harness-Manager-3.0.0-arm64.AppImage`
- 자동 업데이트 매니페스트: `latest.yml`, `latest-linux.yml`, `latest-linux-arm64.yml`

## 검증

- `npm test`: 테스트 파일 38개, 테스트 217개 통과(Windows)
- `npm run typecheck`, `npm run build` 통과
- `npm run dist`로 Windows 설치본을 만들고, 패키지 앱에서 `ELECTRON_RUN_AS_NODE` hm CLI 실행을 확인
- 개발 PC에서 상태판·설치·위저드(dry-run 완주)·가져오기·정리 화면을 직접 확인했고, `hm install`로 이 PC의 jinmin 마켓플레이스 전환과 Codex 플러그인·MCP 등록을 실제로 실행
- `scripts/bootstrap.ps1`: `-DryRun`과, 임시 홈·임시 clone에서 clone→빌드→doctor→install 미리보기까지 실제 실행
