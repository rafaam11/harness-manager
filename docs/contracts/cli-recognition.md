# CLI 인식 진단과 PC 상태 보고

## 검사 범위와 증거

첫 방문은 Codex의 CLI 인식 목록이며 마지막 CLI 선택과 검색을 기억한다. 공통 탭은 공유 기준을 관리한다. CLI 설정·확장은 각 CLI의 하위 탭이다.

`recognition:scope(false)`는 프로젝트 밖의 전역 검사 디렉터리를 준비한다. `true`는 main의 폴더 선택기로 고른 프로젝트에 불투명 범위 ID를 부여한다. 렌더러가 임의 경로를 실행 위치로 전달할 수 없다. 프로젝트 파일은 읽기 전용이다.

`recognition:list({provider, scopeId, refresh})`는 파일·활성 설정과 구조화된 CLI 결과를 합친 작업대 스냅샷을 반환한다. Codex는 새 `app-server` 프로세스에서 initialize → initialized → skills/list(forceReload)를 사용한다. thread/turn을 시작하지 않는다. 기존 앱·MCW 세션의 상태와 실행 성공을 증명하지 않는다. 이름만으로 합치지 않고 실제 경로와 소속 플러그인을 대조한다. 호환용 `catalog:codex-visible-skills`도 같은 어댑터를 사용하며 오류를 빈 목록으로 바꾸지 않는다.

Claude는 현재 어댑터에서 모델·hook·MCP 실행 없이 스킬 목록을 확인하는 인터페이스를 검증하지 못했으므로 파일·설정 관측과 CLI 버전만 제공한다. `--init-only`는 hook을 실행하므로 기본 진단에 사용하지 않는다.

검사 기록은 앱 상태의 `workbench/recognition.v1.json`에 CLI·범위별로 저장한다. CLI 버전, 설정, 발견된 패키지 내용·목록·링크 변경을 지문으로 검사한다. 탐색 상한이나 읽기 실패도 재확인 필요다. 실패·취소 시 이전 성공 목록과 시각을 보존하되 현재 인식 성공으로 표시하지 않는다. 자동 확인을 대체할 수 있는 진단은 수동 적용·복원에 우선권을 양보한다.

플러그인 스킬은 패키지 관리로 연결하며 시스템 스킬은 편집·복사하지 않는다. 충돌 해결의 `changes:resolved-receive`는 선택을 적용한 기준으로 PC 변경 검토를 준비한다. 최종 적용 전까지 기준·PC 파일을 쓰지 않으며 기존 지문·원격 확인·저널 경로를 따른다.

## 제한된 예제 검사

`examples:generate`는 CLI·모델·생성/실행 각각의 추정 비용 상한·시간 제한을 입력받는다. 사용자가 버튼으로 요청한 경우에만 모델을 호출한다. `examples:execute`는 서버에 저장된 검토 토큰만 받는다. 입력에 임의 명령·실행 위치·도구를 추가할 수 없다.

현재 지원하는 검사는 Claude의 텍스트 예제다. 로컬 CLI help에서 제한 모드 지원을 확인한 뒤 `--bare --restricted --tools "" --disallowedTools * --strict-mcp-config`와 빈 MCP 설정, hook 비활성, 세션 미저장, 모델·비용·시간 제한을 함께 적용한다. 프롬프트와 스킬 본문은 stdin으로만 전달한다. 도구·외부 연결이 필요한 계획, 임의 명령, 지원하지 않는 검증 조건은 거절한다. 허용하는 검증은 반환된 텍스트에 지정 문자열이 포함되는지의 독립 검사다. 배포·전송·설치는 모의 텍스트까지 가능하다.

스킬 경로·본문·패키지 지문을 유지하고 실행 전 재대조한다. 임시 폴더는 HM이 만든 경로만 정리한다. 본문을 모델에 제공한 사실은 증거로 남기지만 Skill 도구 사용을 확인했다고 표시하지 않는다. 참조 파일·스크립트 실행과 일반 업무 성공을 보장하지 않는다. Codex는 모든 도구·외부 연결 차단을 확인한 어댑터가 없어 예제 생성을 거절한다. 이 제한은 UI에도 표시한다. 비용은 CLI 추정치이며 실제 청구의 엄격한 상한이 아니다.

취소·시간 초과·출력 상한·인증 오류를 처리한다. 결과는 종료 상태, 본문 제공 증거, 산출물 검사로 구분한다. 최근 결과 100개는 범위·항목 ID와 함께 `workbench/example-evidence.v1.json`에 로컬 저장하며 PC 보고에는 포함하지 않는다.

## PC 보고 형식

PC ID는 무작위 UUID이며 별칭은 사용자가 정한다. 호스트명·사용자명을 읽어 별칭으로 쓰지 않는다. `pc-status:preview`가 허용 필드로 새 보고를 만들고 비공개 원격 상태를 확인한다. `pc-status:send(token)`은 검토한 보고만 보낸다.

형식은 `harness-manager-pc-status`, version 1이며 원격의 `pc-status/v1/<pcId>.json`을 쓴다. 프로필 bundle·자동 적용 정의와 별개다. 식별자, CLI·항목 버전, 인식/활성/공유 기준 상태, 내용 지문, 확인 시각만 포함한다. 절대경로·프로젝트별 결과·지침 본문·인증 정보·프롬프트·로그는 제외한다. 원격 데이터의 알 수 없는 필드도 거절한다.

매 전송 전 비공개 여부·연결·원격 HEAD를 재확인하고 전용 클론에서 해당 PC 파일만 commit한다. force push는 사용하지 않는다. 다른 PC의 동시 전송으로 HEAD가 바뀌면 다시 검토한다. 보고 수신은 설정을 적용하지 않으며 마지막 보고 시각만 표시한다. 설치 가능한 출처가 없는 항목은 설치할 수 있다고 표시하지 않는다.
