# CLI 설정과 확장 관리 (v5)

`이 PC`는 공통 / Claude Code / Codex로 나눈다. 공통 스킬·지침·툴체인은 공통에서 보고, 특정 CLI에서만 관측한 구성요소는 해당 CLI의 스킬·연결에서 본다. 설정·확장은 해당 CLI 탭에서 관리한다. 앱 설정은 HM 자체 동작을 맡는다.

## 카탈로그와 값

Codex 공식 JSON Schema와 Claude 공식 설정 색인·SchemaStore 스키마를 번들한다. 현재 파일에만 있는 알 수 없는 키도 표시한다. 공식 문서의 버전 제한, 조직 정책, 인증 정보, 프로젝트·Codex 프로필 설정과 전용 MCP/확장 키는 읽기 전용이다. 버전 제한이 있는 설정의 설치 버전을 확인하지 못하면 쓰기를 허용하지 않는다. 알 수 없는 형식도 쓰기 전에 거절한다.

문자열·숫자·선택값·배열·객체를 구조화된 폼으로 편집하고 복합 값은 선택한 값만 JSON으로 편집할 수 있다. 저장된 PC 값·원하는 값·기본값·출처를 구별한다. 조직 정책이나 실행 중인 세션의 최종 적용값을 알아냈다고 표시하지 않는다. 민감 필드는 가려 표시한다.

## 저장 형식

`home/cli-settings.v1.json`:

```json
{
  "schemaVersion": 1,
  "settings": [
    { "provider": "codex", "path": ["model"], "operation": "set", "value": "chosen-model" },
    { "provider": "claude", "path": ["permissions", "allow"], "operation": "set", "value": ["Read"] },
    { "provider": "codex", "path": ["notify"], "operation": "remove" }
  ],
  "extensions": [
    { "provider": "claude", "id": "guard@jinmin", "enabled": false }
  ]
}
```

경로는 문자열 조각 배열이다. 점이 든 플러그인 ID를 경로 구분자로 해석하지 않는다. 같은 provider의 중복·겹치는 상하위 경로와 prototype 키를 거절한다. `set`은 배열도 정확히 교체한다. `remove`는 선택한 값을 지워 CLI 기본값을 사용하며 다음 install에서도 유지한다. 관리 해제는 해당 의도를 기준에서 빼고 PC 값을 유지한다. 상위 객체를 이미 관리한다면 상위 편집기에서 변경하거나 먼저 관리 해제한다.

처음 편집하는 기존 관리 키는 기존 관리 목록에서 빼 이중 관리를 방지한다. 기존에 상위 객체 전체를 관리했다면 편집하지 않은 형제 키는 기존 관리 목록에 남긴다. 인증 정보는 이 형식으로 저장하지 않는다. PC 고유 경로를 포함하는 값은 `local/cli-settings.local.json`에 같은 형식으로 따로 저장하며 기본 내보내기·동기화에서 제외한다. 배열에 경로가 하나라도 있으면 전체 배열을 로컬에 둔다.

새 정의가 있는 이동 파일은 **bundle version 3**이다. 기존 v1/v2는 계속 읽으며 자동 변환하지 않는다. 새 설정을 공유하기 전에 모든 PC를 v5로 업데이트한다. 구형 앱은 v3을 쓰기 전에 거절한다.

## 확장과 mod

설치하지 않아도 Claude mod 5개와 Codex jinmin-codex를 표시한다. 설치·켜기·끄기는 각각의 native CLI를 사용하고 자동 제거하지 않는다. 다른 CLI의 대응 확장을 자동으로 켜지 않는다. 설치됨·활성화됨·hook 신뢰·현재 세션 실행은 별개다. MCW 연결은 MCW에서 관리하고 Codex의 대체 기능은 차이를 표시한다.

Claude 옵션은 known mod의 `userConfig` 또는 설치된 캐시의 JSON 메타데이터로 폼을 만든다. TypeScript 모듈을 실행해 옵션을 찾지 않는다. 실제 저장 위치는 `pluginConfigs[pluginId].options[option]`이며 인증 옵션은 편집하지 않는다. 지원 형식은 string / number / boolean / string[]와 enum이다. CLI 홈 밖의 개발 플러그인 메타데이터는 읽지 않는다.

## 적용·복원

렌더러는 provider·설정 ID·값 또는 확장 ID·enabled만 보낸다. main이 스키마와 상태를 확인하고 경로와 명령을 만든다. 기존 변경 검토에서 기준·PC 파일과 설치 명령을 함께 보여 준다. 최초 개인 사본과 선택 변경은 같은 저널에 넣으며 전체 파일 쓰기가 성공한 뒤 선택된다.

JSON은 선택한 경로만 수정한다. TOML은 AST의 값 범위만 바꾸고 미관리 구간과 주석을 보존한다. 루트 키·인라인 표·인용 키·배열 표를 지원하며 전체 파싱 결과가 의도한 값과 다르면 쓰지 않는다. 표 전체를 교체한 경우 그 표 내부 서식은 바뀔 수 있다.

미리보기 이후 기준이나 PC 파일이 바뀌면 중단한다. 외부 명령 후에는 설치·활성 상태를 다시 확인하고 선택한 확장 항목의 변경만 허용해 파일 쓰기를 다시 계산한다. 명령 실패·재검증 실패 시 기준을 저장하지 않고 완료·실패 명령을 기록한다. 외부 설치 명령은 자동 복원하지 않는다. 파일과 기준은 기존 변경 기록에서 함께 복원하며 이후 사용자 변경이 있으면 거절한다.

doctor/install/capture/GitHub 수신은 같은 정의와 projection을 쓴다. capture는 명시적으로 관리하는 값만 갱신하며 확장 상태를 낡은 활성 목록에 중복 추가하지 않는다. 새 설정 변경의 자동 수신은 보류하고 수동 검토한다. 원격 업로드는 수동이다.
